# Loop pencarian dan audit target 4,7

Tanggal: **8 September 2026**. Dokumen ini mencatat loop pencarian terbaru dan memisahkan tiga hal: rating riset dari sumber, bukti lokal workspace, dan skor aktual MVP. Angka 4,7 hanya dianggap tercapai bila seluruh gate aktual lulus.

## Prosedur loop

Setiap putaran menjalankan urutan yang sama:

1. Cari kandidat melalui sumber primer atau halaman proyek yang memuat demo dan source code.
2. Baca spesifikasi, repository, status deployment, test suite, serta keterbatasan yang dinyatakan pembuatnya.
3. Cari produk atau standar yang sudah memiliki kemampuan inti yang sama.
4. Beri empat dimensi `Innovation`, `Technical Feasibility`, `Uniqueness`, dan `Design` dengan angka desimal sebelum pembulatan.
5. Hitung rata-rata memakai pembulatan half-up satu angka desimal.
6. Tandai bukti sebagai `local_replayable`, `external_source_backed`, `external_reference_implementation`, atau `existing_project_benchmark`.
7. Beri `actual_score` hanya jika kontrak atau fork dijalankan, verifier kedua lulus, flow testnet/live dapat diulang, dan user validation plus impact measurement tersedia.

Script yang menjalankan perhitungan ledger adalah [research/spikes/candidate_audit_loop.py](../../research/spikes/candidate_audit_loop.py:1). Ia sengaja mengembalikan `actual_score: null` untuk kandidat yang gate-nya belum lengkap atau yang sudah merupakan proyek publik. Artefak JSON ditulis ke `evidence/generated/research-spikes/candidate_audit_loop.json`.

## Audit kandidat teratas

### MemoryLineage Auditor / ERC-8350

ERC-8350 memposisikan state memori agen sebagai sejarah transisi yang dapat diverifikasi tanpa menaruh isi memori di chain. Thread resminya menyebut deployment Sepolia, sedangkan repository memuat reference Solidity/TypeScript dan golden vector. [Thread ERC-8350](https://ethereum-magicians.org/t/erc-8350-agent-memory-state-registry/29098), [repository ERC-8350](https://github.com/AwareLiquid/ERC-8350), [PR upstream](https://github.com/ethereum/ERCs/pull/1910).

Bukti lokal yang benar-benar tersedia adalah model commitment dan linear-history di [verifier/python/memory_lineage/model.py](../../verifier/python/memory_lineage/model.py:1): suite workspace 18/18, runner tujuh kasus, enam mutasi tidak lolos, seluruh published-vector check benar, dan replay mismatch nol. Ini belum membuktikan bytecode Solidity, EOA/ERC-1271 authorization, event indexing, transaksi Sepolia, atau semantic truth isi memori.

Rata-rata risetnya adalah `(4,6 + 4,0 + 3,9 + 4,5) / 4 = 4,25`, dibulatkan half-up menjadi **4,3**. Jalur target conditional 4,7 masih masuk akal secara aritmetika dengan dimensi `4,8 / 4,6 / 4,7 / 4,8`, rata-rata `4,725`, tetapi angka tersebut belum boleh ditulis sebagai skor aktual.

### MemoryRights / ERC-8264 plus Portable Capsule

ERC-8264 mendefinisikan `readMemory`, `writeMemory`, `deleteMemory`, dan `exportMemory`; companion Capsule mendefinisikan bundle owner-signed, content-addressed, dan Merkle-committed. Reference repository mengklaim self-test, kontrak Solidity, 21/21 Foundry tests, deployment pada tiga testnet EVM, serta anchor Bitcoin. [ERC-8264](https://ethereum-magicians.org/t/erc-8264-ai-agent-memory-access-rights/28584), [Capsule/Body Lease](https://ethereum-magicians.org/t/erc-8269-body-lease-and-credential-broker/28597), [reference repository](https://github.com/clavote-boop/rmem-gateway).

Audit menahan ratingnya pada **4,1**, walaupun bukti teknis reference lebih konkret daripada proposal biasa. Alasannya: implementasi bukan milik workspace, test dan laporan berasal dari author/reference yang sama, deletion finality dan pagination masih menjadi open question, dan produk memory governance yang sudah ada membuat uniqueness turun. Ini kandidat integrasi atau benchmark, bukan bukti bahwa kita sudah mempunyai MVP 4,7.

### FlexGov dan proyek SwapVM

FlexGov adalah benchmark yang sangat kuat: halaman proyek menjelaskan canonical report, metrik konsentrasi, empat recount rule, provenance, stable hashes, Graph pagination, dan 34 tests. [FlexGov](https://ethglobal.com/showcase/flexgov-ooe2m). KSwap-VM bahkan menyediakan repository dan verification page dengan negative controls, tetapi repository sendiri menyatakan 20 dari 52 opcode dimodelkan dan theorem lapis kedua masih `ADMITTED` pada beberapa bagian. [KSwap-VM showcase](https://ethglobal.com/showcase/kswap-vm-aix5n), [repository](https://github.com/vovunku/swap-vm-verified).

Keduanya menaikkan standar pembuktian yang harus dipenuhi, tetapi tidak menjadi pilihan kita. Membangun ulang governance report atau formal SwapVM proof akan memberi overlap langsung sehingga skor Uniqueness tidak mendukung 4,7 untuk submission baru.

## Gate aktual 4,7

Syarat berikut harus dilalui oleh MemoryLineage sebelum target conditional dipromosikan menjadi skor aktual:

| Gate | Bukti yang harus ada | Status sekarang | Stop condition |
| --- | --- | --- | --- |
| Contract conformance | Solidity/Foundry atau fork yang menghasilkan transition, predecessor, sequence, authorizer, dan state root yang sama dengan vector | Belum ada | Python saja dianggap model lokal |
| Authorization | EOA dan ERC-1271 valid; signer berbeda, signature stale, dan wrong space ditolak | Belum ada | Hash cocok tetapi otorisasi tidak diuji |
| Independent replay | Verifier kedua membaca evidence export dan menghitung hasil tanpa memanggil evaluator/publisher | Replay lokal ada, tetapi belum lintas implementasi | Verifier berbagi fungsi inti |
| Adversarial mutation | Rollback, gap, fork, unauthorized writer, locator substitution, payload tamper, dan memory poisoning | Enam mutasi lokal ada; poisoning agent nyata belum ada | Mutasi hanya mengubah field kosmetik |
| Testnet/live | Minimal satu transition valid dan satu penolakan dapat dibaca ulang dari chain/indexer | Belum ada | Mock/local chain tanpa perbedaan disebut testnet |
| User and impact | Developer dapat membedakan valid/stale/poisoned; waktu replay, gas, false reject, dan mismatch dicatat | Belum ada | Tidak ada pembanding atau angka hasil |

Selama enam status ini belum lengkap, loop harus menyebut **conditional 4,7**, bukan **actual 4,7**. Pencarian tambahan tidak dapat menggantikan kontrak, verifier independen, transaksi, atau uji pengguna.

## Keputusan loop

Ledger tiga putaran tambahan tidak menemukan `actual_4_7`. Ia menemukan satu jalur conditional yang paling terukur, yaitu MemoryLineage, dan satu challenger kuat yang sudah memiliki reference implementation, yaitu MemoryRights/Capsule. Karena MemoryRights sudah memiliki produk referensi yang sangat dekat, prioritas kerja tetap MemoryLineage dengan batas MVP yang sempit.

Loop berikutnya seharusnya mengerjakan gate Contract conformance dan Independent replay. Jika salah satu gagal, kandidat tidak boleh dinaikkan; keputusan harus kembali ke kandidat yang memiliki bukti lokal paling kuat, bukan ke angka target.

Pencarian ini bukan sensus seluruh ekosistem. Halaman showcase dan forum standar dapat berubah, dan tidak ditemukannya produk identik pada query tertentu bukan bukti nonexistence. Semua klaim keunikan harus tetap ditulis sebagai hasil pencarian terbatas.

## Addendum: hasil conformance EVM lokal

Conformance probe yang direncanakan di atas sekarang sudah dijalankan pada
workspace. Kontrak lokal mengikuti API dan domain utama ERC-8350 v1; audit
menemukan golden vector cocok, empat transition valid, EOA dan ERC-1271
berfungsi, rotasi authorizer menaikkan `configNonce`, dan 20/20 mutation
ditolak. Verifier Python kedua mereplay evidence tanpa mengimpor implementasi
JavaScript dan menghasilkan `replay_mismatches=0`.

Perubahan ini menaikkan status bukti teknis lokal, tetapi tidak mengubah
`actual_score`: deployment publik workspace, reread RPC/indexer kedua, dan
validasi developer/impact masih kosong. Probe live pada dua RPC hanya membaca
deployment referensi upstream. Karena itu ledger tetap menghasilkan
`NO_ACTUAL_4_7;_CONDITIONAL_PATH_ONLY` sampai gate eksternal tersebut memiliki
transaction hash, bytecode hash, reread independen, dan hasil uji pengguna.
