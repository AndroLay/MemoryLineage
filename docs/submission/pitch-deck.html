01 · The Problem

The file opens. The history may be wrong.

After an outage, restoring an old snapshot can silently rewind an agent while newer committed states already exist.

03 · The Innovation

Why this recovery workflow is different.

The contribution is the recovery workflow around existing standards—not a new cryptographic primitive.

Restore onlyReopens the file, but does not show whether it is the latest shared state.
Local signed logShows who signed a record; by itself, it may not give other parties an independent latest checkpoint.

04 · The Impact

Make recovery decisions reviewable.

When storage and resume approval are split across people, each needs the same evidence.

OperatorSee what came back

Compare the restored backup with the recorded latest state before handing control back.

ControllerApply one visible rule

Latest and approved may pass the demo gate; older stays practice-only; unknown states are held.

AuditorCheck the same evidence

Replay the bundle independently and see altered evidence fail with a specific mismatch.

Prototype evidence: a synthetic local case rejects the stale step and keeps the reference loader from running. Production outcomes and user impact have not been measured.

Current Limitations

Local replay has a clear trust boundary.

Evidence and recovery

  • Chain origin: offline replay checks the address format, not which contract or network produced the bundle.
  • Complete history: recovery needs saved logs or bundles; the demo has no history indexer.
  • Other trust checks: past smart-wallet approvals are not replayed; network reads use one RPC source.

Product and meaning

  • Deployment: Demo Space V2 is synthetic and local; no same-space public deployment is shown.
  • Runtime assurance: the gate is a local reference adapter, not a production framework integration or formal audit.
  • Real-memory privacy: extra privacy protection for real memories is not integrated or audited.
  • Memory meaning: truth, safety, reasoning quality, and memory-to-action causality are out of scope.
External reproduction and production adoption are not claimed09 / 10

05 · Future Scope

What must be proved before real use.

Each milestone has a checkable exit condition; the current demo has not passed these production gates.

01 · CHAIN SOURCETrust the source

Verify deployed code and state against a block checked through a trusted source.

02 · HISTORYRebuild the same history

Replay saved logs and bundles to the checked registry head; stop if records are missing.

03 · REAL RUNTIMEGate one real loader

Prove current, approved state proceeds; old, diverged, or unknown state stays blocked.

04 · PEOPLE & PRIVACYValidate before real memory

Measure unaided reviewer success; test privacy-key backup and recovery.
